    A SQL practice bench, in one script tag.

    sql-workbench is a web component: a full SQLite engine, a query editor, a schema browser, and a run journal compiled into a single JavaScript file. Drop it into any page — a lesson, a docs site, a course — and your users can practice real SQL. Nothing to install, nothing leaves the browser.

    Add it to your page

    One script, one element. The file is ~1.5 MB (614 KB gzipped) and makes zero side requests — the SQLite engine, worker and all, is inside it.

    <script type="module"
        src="https://cdn.jsdelivr.net/gh/udit-001/sql-workbench@v0.2/dist/sql-workbench.js"></script>

<sql-workbench namespace="my-app" style="display:block;height:560px"></sql-workbench>

    Prefer hosting it yourself? Download sql-workbench.js from the releases and serve it from your own origin.

    It matches your app, not the other way round

    The bench follows your page's html[data-theme] and the OS color scheme — try the ◐ button in the header: both benches above and below flip with the page. For a full rebrand, override design tokens on the element; they win even against dark mode: 

    sql-workbench {
  --wb-bg: #24283b; --wb-surface: #1f2335; --wb-accent: #bb9af7;
  --wb-text: #c0caf5; --wb-heading: #7aa2f7; --wb-border: #414868;
}
sql-workbench::part(run-button) { border-radius: 999px; }

    Tokens exist for every surface color, the SQL syntax palette, and fonts (--wb-bg, --wb-surface, --wb-accent, --wb-kw, --wb-str, --wb-num, --wb-mono, …). Styleable parts: editor, run-button, reset-button, results, schema, diagram, history, statusbar.

    Each instance keeps its own data

    Two benches on one page don't share anything. The namespace attribute gives each one a private journal and private imported tables — one per lesson, per user task, or per tab: 

    <sql-workbench namespace="lesson-1"></sql-workbench>
<sql-workbench namespace="lesson-2"></sql-workbench>

    Start learners mid-thought

    The sql attribute pre-fills the editor, so a lesson can pose a half-written query and let the learner finish it. The card demo above uses it. You can also pass ?sql=… in the URL on a standalone page, and dataset loads a named dataset instead of the built-in demo.

    Watch what learners run

    Every query, import, and reset is journaled. Get them live as DOM events, read the whole journal on demand, or export it as Markdown: 

    bench.addEventListener("workbench-event", (e) => {
  // e.detail: { type: "query" | "csv-import" | "dataset-reset", sql, ok, rows, ms, error … }
});

const events = await bench.events();      // newest first, same shapes
const md = await bench.exportMarkdown();  // paste-ready practice log

    Reference

    Attributes — mode and theme react live; namespace, dataset, sql are read at connect.

    AttributeEffect
    mode="card"editor + Run/Reset only
    themelight / dark override; else follows the page
    namespaceprivate journal + imported tables
    datasetnamed dataset instead of the built-in demo
    sqlboot-time editor prefill

    Methods & events

    MemberWhat it does
    run(sql)fills the editor, executes, journals
    reset()restores the dataset's seed data
    events()journal entries, newest first
    exportMarkdown()journal as a Markdown practice log
    setTheme(t)"light" or "dark"
    workbench-eventfired for every journaled event

    Where the data lives

    Everything runs in the learner's browser: SQLite in memory inside the tab, the journal and imported CSVs in IndexedDB under your namespace. No server, no telemetry.
